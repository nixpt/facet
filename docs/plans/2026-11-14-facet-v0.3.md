**Plan only. Nothing here is implemented until vega or the captain picks the scope.**

Baseline: main @c2d6797 (v0.2.0), plus FACET-2 (facet#3, v0.2.1, required repeating positional).
Toolchain: the prebuilt `/workspace/bin/release` @7e6696db. All claims below were probed on it, except AOT, which was read from source.

## 1. What changed upstream since the v0.1 design

The 2026-10-31 design doc and the README were written against limits that are now gone. altair probed each one on 7e6696db.

| v0.1 limit | status @7e6696db | effect on facet |
|---|---|---|
| `import` compiles to `module.load`, which no backend implements | **fixed**, CRUSH-110 (83331dc5): imports resolve at compile time. `import facet`, `import facet { facet_parse }`, `-L <dir>` / `CRUSH_PATH`, and crush-pkg path deps all work | facet can be consumed by import instead of by concatenation |
| crush-pkg path deps not seen by `crush-pkg run` (CRUSH-348) | **fixed** in 7860d803 (#361) | the `examples/consumer` workaround ("run the built .cvm") is no longer needed |
| `sys.exit(n)` under crush-pkg drops output and errors (CRUSH-349) | **fixed** in 7860d803 | facet's exit-2 / exit-70 policy works under crush-pkg |
| AOT lowerers reject `sys.args`, `sys.exit`, `conv.*` and `env.get` (C backend also rejects `try`) | **still open**, read from source only. There is no AOT binary in the release set, and crush-aotc is being deleted (#452). The C-backend `try`/`env.get` claim is unverified | facet stays **VM-only** in v0.3 |

Import has two limits that shape the design:
- **Only public names import.** `__facet_*` helpers are not reachable from an importer. facet_test.crush calls internals, so it keeps the concatenation path.
- **An imported module may hold only definitions.** Its `main` is ignored, and any other top-level statement is an error. facet.crush is already definitions-only: altair confirmed that `import facet` compiles and runs it.

altair also confirmed that `examples/consumer` now runs under `crush-pkg run -- --help` with exit 0.

- **Bare names need the brace form.** Probed by arisu on polish:
  - Plain `import facet` namespaces the functions as `facet.facet_run(...)`. Existing code that calls `facet_run` / `facet_fail` bare fails with `[compile] Undefined function: facet_fail`.
  - `import facet { facet_run, facet_fail }` plus `-L <facet dir>` compiles. polish's `check`, `fmt` (no files → exit 2) and `--help` all behave.
  - So the docs (FACET-4) must lead with the brace form, or with the `facet.`-prefixed calls, and say which one.

**No crush-ast tickets are needed for v0.3.** If vega puts AOT in scope, altair files the AOT-lowerer gap (sys.args, sys.exit, conv.parse_int/to_float/to_str, env.get) as a crush-ast ticket against the successor of crush-aotc. No ticket covers it today.

## 2. Gaps against the v0.1 design

| design item | state today | v0.3 |
|---|---|---|
| module split (main / spec / lex / coerce / render) | one flat `facet.crush`, forced by the missing imports | **out.** Splitting would make the helpers public (only public names import), which is worse than one flat file. Revisit only if helpers get a real namespace |
| `facet.err()`, last error for embedding callers | replaced by `facet_parse_debug` / `facet_resolve` returning `{ ok, error }` | **out.** It is superseded; drop it from the doc |
| env fallback in core | separate `facet_env.crush`, VM-only | **out** (blocked on AOT). Now importable as its own module (`import facet_env`) |
| FastVM / JIT | "same code path, untested" | **out**: nothing changes until the differential harness wires caps into FastVM |
| README "no imports" + CRUSH-348/349 caveats | stale | **in** (T1) |

## 3. Proposed v0.3 scope (altair agrees)

Each ticket is small and gets its own worktree and draft PR. The gate is the same as FACET-2's:
- `test/run.sh` green on the prebuilt crush-run, with counts before and after;
- every demo runs `--help` plus one real invocation;
- usagi re-runs the gate on the committed head;
- altair reviews.

| id | ticket | done when |
|---|---|---|
| **FACET-4** | **Import-first docs and demos.** Rewrite the README "how to consume" section: `import facet` first, then a crush-pkg path dep, with concatenation kept as the fallback. Drop the 348/349 caveats. Port `demo/*.crush` and `examples/consumer` to `import`. Fix the env_greet header: the `--env` grant goes **before** `--`, and is needed even for `--help`, because the grant check covers the whole program. Add a test/run.sh step that runs one demo through `import` | each demo runs via `crush-run run -L . demo/x.crush` with no `cat`; test/run.sh still concatenates for the internals |
| **FACET-5** | **Count flags.** A flag with `count: true` returns an int: `-vvv` → 3, `-v -v` → 2, absent → 0. Help shows `(repeatable)` | new checks for bundling, separate tokens, and long-form repeats; spec check rejects `count` together with a `type` |
| **FACET-6** | **Option groups.** Spec key `groups: [ { exclusive: ["--json", "--table"] }, { together: ["--user", "--pass"] }, { one_of: [...] } ]`. Errors are argparse-style, e.g. `--json and --table are mutually exclusive`. Applies on subcommands too | checks for each group kind; facet_check_spec rejects names a group references but the spec doesn't declare |
| **FACET-7** | **Dogfood: polish on import** (the acceptance test). In nixpt/polish (altair's lane, so this is a PR there that altair approves), replace `scripts/build.sh` concatenation of facet with `import facet { facet_run, facet_fail }` (the only two facet names polish uses) via `-L` or a crush-pkg path dep. polish's own four `src/*.crush` files share `__polish_*` helpers, so they keep concatenating each other; only facet moves to import. This was probed and works on the FACET-2 head. Also refresh polish's README line "no source-level imports yet (CRUSH-110)", which is now stale. Drop polish's own empty-file-list check, which FACET-2 makes redundant. **Needs FACET-2 (facet#3) merged first**: without it, `polish fmt` with no files exits 0 | polish's tests pass. `polish --help` and `polish check <file>` keep **the same exit codes**. With no files, the message changes from polish's "no files given" to facet's standard `missing required argument 'files'`, still exit 2. Note the change in polish's CHANGELOG. polish's `tests/cli.sh` checks only exit codes, so it stays green |
| FACET-8 *(only if vega wants it)* | AOT envelope: altair files the crush-ast ticket. facet does nothing until it lands | n/a |

Order: FACET-4 first, because it changes how every later PR's demos run. FACET-5 and FACET-6 can run in parallel after it. FACET-7 runs last, against the released 0.3.0.
Release: 0.3.0 once FACET-4..7 are merged. The CHANGELOG gets one entry per ticket.

**Explicitly out of v0.3:**
- Shell completions. They are a separate output format; revisit when buttershell asks for a CAISON spec.
- facet_env merged into core (blocked on AOT).
- The module split.
- AOT support.
- New value types.

## 4. Consumer to dogfood

**polish** (nixpt/polish, a Crush formatter and linter, `polish fmt|lint|check FILE...`).
- It is a real fleet CLI and already depends on facet. It is where facet#2 was found (polish#1).
- Its `scripts/build.sh` concatenates `../facet/facet.crush` today. That makes it the exact case import is meant to replace.
- polish is altair's repo. Our soldiers write the FACET-7 change, and altair reviews and approves it there.
